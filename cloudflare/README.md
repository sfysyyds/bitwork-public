# Candidate response-header rule

`response-header-transform-rule.json` is one candidate rule for Cloudflare's zone-level `http_response_headers_transform` phase. It matches only requests whose host is exactly `bitwork.top` and whose Cloudflare `ssl` boolean is true (the client-to-Cloudflare connection is encrypted); it does not match `www.bitwork.top` or `work.bitwork.top`. The `ssl` field is documented by [Cloudflare](https://developers.cloudflare.com/ruleset-engine/rules-language/fields/reference/ssl/). This repository does not contain the live Cloudflare ruleset, and this candidate has not been deployed.

Before applying it, use the Cloudflare Rulesets API to list the zone's rulesets and read the current ruleset for `http_response_headers_transform`. Back up that full response first. If one exists, append this rule (or replace only the rule with the same `ref`) while retaining every other rule and ruleset field; do not PUT this single-rule file as the complete `rules` array. If no phase ruleset exists, create a zone ruleset in that phase, then add this rule. Read the ruleset back and verify the exact host/`ssl` expression and headers before treating it as active. No API token or production write is included here.

Cloudflare's API uses `action: "rewrite"`, header operations under `action_parameters.headers`, and the `http_response_headers_transform` zone phase. See [Create a response header transform rule via API](https://developers.cloudflare.com/rules/transform/response-header-modification/create-api/) and [API parameter reference](https://developers.cloudflare.com/rules/transform/response-header-modification/reference/parameters/).
